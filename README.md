# 🫀 CardioCare ML: Cardiovascular Disease Prediction System

A complete, beginner-friendly, full-stack Machine Learning web application designed to predict the risk of cardiovascular disease from 12 clinical patient biomarkers.

Built with **React + Vite** for the frontend, **FastAPI + Scikit-Learn** for the backend, and isolated using a dedicated **Python Virtual Environment (`venv`)**.

## 🌟 Key Features

- **Trained on Real Clinical Data**: 1,000 patient records across 12 clinical biomarkers.
- **High-Performance ML Model**: Evaluated with a stratified 80/20 train-test split. The **Random Forest Classifier** achieves **98.5% Accuracy** and **0.9987 ROC-AUC**.
- **Consistent Feature Preprocessing**: `StandardScaler` is fitted during training, serialized using `joblib`, and reused identically in FastAPI for zero training-serving skew.
- **Dynamic Performance Dashboard**: The frontend queries the `/metrics` endpoint to display real test accuracy, confusion matrix, and feature importance weights dynamically (no hardcoded numbers).
- **Interactive Prediction Interface**: Form input with live validation, quick "Load Sample High Risk" and "Load Sample Low Risk" presets for college viva demonstrations, and an animated probability bar.
- **Configurable Architecture**: Full support for environment variables (`VITE_API_URL`, `CORS_ORIGINS`, `PORT`) for local development and cloud deployment.

## 🐍 Python Virtual Environment (`venv`) Guide

### 1. What is a Virtual Environment (`venv`)?
A virtual environment is an isolated directory tree on your computer that contains a specific Python installation alongside a discrete set of installed packages.

### 2. Why Do We Use It?
- **Isolation**: Prevents package version conflicts between different projects on the same machine.
- **Reproducibility**: Guarantees that anyone running your project can install the exact versions required via `requirements.txt`.
- **Cleanliness**: Avoids cluttering or corrupting your system-wide global Python installation.

### 3. How to Create the Virtual Environment
Open PowerShell or your terminal, navigate into the `backend/` folder, and run:
```powershell
cd backend
python -m venv venv
```

### 4. How to Activate the Virtual Environment
- **On Windows (PowerShell):**
  ```powershell
  .\venv\Scripts\Activate.ps1
  ```
  *(If PowerShell blocks scripts, run `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` once, then activate).*
- **On Windows (Command Prompt):**
  ```cmd
  venv\Scripts\activate.bat
  ```
- **On macOS / Linux:**
  ```bash
  source venv/bin/activate
  ```
When activated, you will see `(venv)` prefixed in your terminal prompt.

### 5. How to Deactivate the Virtual Environment
When you are finished working:
```bash
deactivate
```

### 6. How to Install Required Packages Inside `venv`
With `venv` activated:
```powershell
pip install fastapi uvicorn pandas numpy scikit-learn joblib python-dotenv
```
To freeze the exact installed versions into `requirements.txt`:
```powershell
pip freeze > requirements.txt
```

### 7. How Another Person Recreates the Environment
Any collaborator or evaluator can set up your exact backend in seconds:
```powershell
cd backend
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

## 🚀 How to Run the Project Locally

### Step 1: Train the Machine Learning Model (Optional)
The pre-trained model artifacts (`model.pkl`, `scaler.pkl`, and `metrics.json`) are already generated and included in `backend/`.
If you wish to re-train the models or run experiments:
- Open and execute the cells in `backend/train_model.ipynb` using VS Code, JupyterLab, or Jupyter Notebook.
*Executing the notebook runs data preprocessing on `cardio_train.csv`, benchmarks all candidate models, and regenerates `model.pkl`, `scaler.pkl`, and `metrics.json`.*

### Step 2: Start the FastAPI Backend
Inside the `backend/` directory, use the project's virtual environment:
```powershell
cd backend
.\venv\Scripts\python.exe app.py
```
*(Or if you prefer uvicorn directly: `.\venv\Scripts\python.exe -m uvicorn app:app --reload --port 8001`)*

- **Health Check**: Open [http://localhost:8001/](http://localhost:8001/) in your browser.
- **Swagger Documentation**: Open [http://localhost:8001/docs](http://localhost:8001/docs) to view interactive API documentation.
- **Model Metrics**: Open [http://localhost:8001/metrics](http://localhost:8001/metrics) to inspect live JSON evaluation scores.

### Step 3: Start the React Frontend
In a **new terminal window**, navigate to the `frontend/` directory:
```powershell
cd frontend
npm install
npm run dev
```
Open [http://localhost:5173/](http://localhost:5173/) in your web browser.

## 📊 Dataset Features Reference

The model utilizes 12 clinical indicators:

1. **`age`**: Patient age in years (20 - 80).
2. **`gender`**: Biological sex (1 = Male, 0 = Female).
3. **`chestpain`**: Chest pain type (0: Typical Angina, 1: Atypical Angina, 2: Non-Anginal, 3: Asymptomatic).
4. **`restingBP`**: Resting blood pressure upon admission in mm Hg (normal: 90 - 140).
5. **`serumcholestrol`**: Serum cholesterol level in mg/dl (normal: < 200).
6. **`fastingbloodsugar`**: Fasting blood sugar > 120 mg/dl (1 = True, 0 = False).
7. **`restingrelectro`**: Resting ECG findings (0: Normal, 1: ST-T abnormality, 2: Ventricular hypertrophy).
8. **`maxheartrate`**: Maximum heart rate achieved during exercise stress test in BPM (71 - 202).
9. **`exerciseangia`**: Angina induced by exercise (1 = Yes, 0 = No).
10. **`oldpeak`**: ST depression induced by exercise relative to rest (0.0 - 6.2).
11. **`slope`**: Slope of the peak exercise ST segment (0: Upsloping, 1: Flat, 2: Downsloping, 3: Other).
12. **`noofmajorvessels`**: Number of major coronary vessels colored by fluoroscopy (0 - 3).

## 🌐 Deployment Instructions

### Backend Deployment (e.g., Render / Railway)
1. **Repository**: Push your code to GitHub (remember: `venv/` is excluded by `.gitignore`).
2. **Root Directory**: Set build/working directory to `backend`.
3. **Build Command**:
   ```bash
   pip install -r requirements.txt
   ```
   *(Artifacts `model.pkl`, `scaler.pkl`, and `metrics.json` are already tracked in git, so Render does NOT need to run Jupyter or train during deployment).*
4. **Start Command**:
   ```bash
   uvicorn app:app --host 0.0.0.0 --port $PORT
   ```
5. **Environment Variables**:
   - `PORT`: Automatically provided by the host (e.g. 10000 or 8000).
   - `CORS_ORIGINS`: Set to your deployed frontend domain (e.g., `https://your-app.vercel.app`).

### Frontend Deployment (e.g., Vercel / Netlify)
1. **Root Directory**: Set root directory to `frontend`.
2. **Build Command**:
   ```bash
   npm run build
   ```
3. **Output Directory**: `dist`
4. **Environment Variable**:
   - `VITE_API_URL`: Set to your deployed backend URL (e.g., `https://your-api.onrender.com`).
   *Do NOT hardcode `http://localhost:8000` in production!*

## 🎓 Viva Voce / Oral Examination Questions & Answers

**Q1: Why was Random Forest selected over other algorithms?**
> *Answer:* We evaluated Logistic Regression, Decision Tree, K-Nearest Neighbors, and Random Forest on the exact same 200-sample test set. Random Forest achieved the highest combination of Test Accuracy (98.5%), F1-Score (98.71%), and ROC-AUC (0.9987). Being an ensemble of decision trees, it reduces overfitting through bagging and provides reliable probability estimations.

**Q2: Why must `patientid` be dropped before training?**
> *Answer:* `patientid` is an artificial surrogate key assigned by the database. It possesses zero physiological relationship to heart disease. If kept, the algorithm could memorize row IDs, leading to spurious patterns and severe overfitting.

**Q3: What is "Data Leakage" and how did we prevent it?**
> *Answer:* Data leakage occurs when test data information inadvertently influences the training process. We prevented this by splitting the dataset into train and test sets *first*, and then fitting the `StandardScaler` *only* on the training split (`X_train`). The test split (`X_test`) was transformed using the fitted training statistics without refitting.

**Q4: How does FastAPI ensure input data validity?**
> *Answer:* FastAPI leverages **Pydantic** models (`HeartDiseaseInput`). Incoming JSON payloads are strictly validated against defined types and range boundaries (e.g., age between 1 and 120, blood pressure between 50 and 300). If an invalid value is supplied, FastAPI automatically rejects the request with an HTTP 422 Unprocessable Entity error before reaching the ML model.

**Q5: What is CORS and why is it configured?**
> *Answer:* Cross-Origin Resource Sharing (CORS) is a browser security mechanism that blocks web pages from making HTTP requests to a different domain or port. Because React runs on `http://localhost:5173` and FastAPI runs on `http://localhost:8000`, FastAPI must explicitly permit the React origin via `CORSMiddleware`.
